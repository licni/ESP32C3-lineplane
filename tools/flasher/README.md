# 線控飛機設定器(Windows,免安裝)

給**不想安裝程式開發環境**的使用者:下載一個 `LineplaneConfig.exe`,接上 ESP32-C3 SuperMini 開發板就能
**燒錄韌體**,**用電腦設定飛控**(和手機看到的網頁完全相同,USB 線或 WiFi 都可以),**設定板子的 WiFi**(熱點名稱,或連家用 WiFi / 手機熱點,連上後直接顯示網址),
**匯出/匯入板上全部設定備份**,**看板子回報的訊息**(翻成中文).

> [!WARNING]
> 燒錄與測試時一律**拆下螺旋槳**. 設定網頁上「開始起飛程序」「手動輸出」這些會讓馬達轉的功能,接 USB 線時和 WiFi 一樣能用,請自己負責安全.

## 下載

**直接下載:<https://github.com/licni/ESP32C3-lineplane/releases/latest/download/LineplaneConfig.exe>**
(永遠是最新版;各版本說明在 [Releases](https://github.com/licni/ESP32C3-lineplane/releases))

不用安裝,直接執行. 第一次打開時 Windows SmartScreen 可能提示「無法辨識的應用程式」(沒有付費簽章),按「其他資訊 → 仍要執行」.

## 接上開發板

用「可以傳資料」的 USB 線接電腦. 程式會自動偵測 ESP32-C3(原生 USB,VID 303A)並選好序列埠;接了好幾片時請確認選的是要用的那一片.
偵測不到時:按住板子上的 **BOOT** 鍵,拔掉再插上 USB,放開 BOOT. 板子焊在 PCB 上不用拆,接得到 USB 孔就好.

## 燒錄頁

1. 「韌體版本」預設最新版(下面顯示這版改了什麼),也可以選舊版. 版本清單來自[公開韌體專案](https://github.com/licni/ESP32lineplane-firmware)的 Releases.
2. 「燒錄方式」:
   - **更新:保留板上設定**(預設):只換程式,板上設定(飛行參數,WiFi)完全不動. 已經在用的板子一律用這個.
   - **全新燒錄:清空設定,回出廠值**:整片重寫(預設先清除整片). 全新空白板子用這個;板子沒有回應時程式也會問你要不要改用它.
3. 按 **開始燒錄**:程式自動下載對應的檔案 → 偵測板子 → **自動備份板上全部設定存成檔案**(`%LOCALAPPDATA%\LineplaneConfig\backups`,
   板子韌體 2026.11.02.2 以上才能備份)→ 燒錄 → 板子重開後**自動檢查**(可以取消勾選):

   | 項目 | 怎麼檢查 |
   |---|---|
   | 晶片 | esptool 連上後讀到的晶片型號要是 ESP32-C3 |
   | 寫入校驗 | 每一段寫完都比對板子上的檢查碼 |
   | 開機與版本 | 送序列指令 `fw`,板子回報的版本要和檔案相同 |
   | 感測器 MPU6050 | 送 `mpu`,沒接或接錯會提示檢查 GPIO5/6 接線 |
   | WiFi | 送 `net`,顯示熱點模式或家用 WiFi 的 IP |

   全新燒錄後設定是出廠值;燒錄前自動備份的檔案可到「設定與備份」頁「匯入備份到板子」寫回.
   隨時可以按「只做檢查」檢查已經燒好的板子.
4. 「進階 ▸」:要燒自己下載的 `.bin` 時在這裡選檔案(程式會讀檔案內容判斷類型,版本,並檢查沒有損壞);「改回自動下載」回到正常流程.

### 背後的兩種韌體檔(一般使用者不用管)

| 燒錄方式 | 用的檔案 | 燒錄位置 | 板上設定 |
|---|---|---|---|
| 更新 | `firmware-版本.bin`(韌體更新檔) | 0x10000,otadata 寫成 boot_app0 | 保留 |
| 全新燒錄 | `lineplane-full-版本.bin`(完整燒錄檔,Releases) | 0x0 整片 | 回出廠值 |

完整燒錄檔 2026.10.07.1 起才有. 選更早的版本做全新燒錄時,程式用最新完整燒錄檔的前 64KB(開機程式,分割表,boot_app0)
接上那一版的韌體更新檔組成完整燒錄檔. 空白板子只能全新燒錄:韌體更新檔沒有開機程式,燒了不會開機.
帶螢幕板(OLED)已不再維護,設定器只燒普通版.

## 設定與備份頁

**連線方式**:
- **USB 線**:用上面選的序列埠. 板子韌體要 **2026.11.02.2 以上**(更舊的板子先在燒錄頁選最新版,勾「保留板上設定」更新).
- **WiFi**:填板子位址. 連家用 WiFi 用 `lineplane.local`(或板子的 IP);電腦連板子熱點時用 `192.168.4.1`.

**開啟設定網頁**:用電腦的瀏覽器打開板子的設定網頁,內容和手機看到的**完全相同**(就是板子上那一份網頁).
- USB 線:程式在電腦上開一個小伺服器(`http://127.0.0.1:隨機埠/`),網頁按的每一個動作都透過 USB 線轉給板子. 程式關掉或 USB 拔掉網頁就斷線,接回後重新整理即可.
  網頁從板子讀出來(依韌體版本快取在電腦),所以永遠和板子的韌體版本一致. 只有兩處不同:「韌體更新」卡換成提示(更新請用燒錄頁),
  新韌體「待確認」不會由 USB 網頁自動確認(確認要證明新韌體的 WiFi 連得上,請用 WiFi 開一次網頁). 其他功能,包括飛行中鎖定設定等安全規則,和 WiFi 完全一樣.
- WiFi:直接開 `http://位址/`,和手機一樣.

**WiFi 設定**(只走 USB 線;改完板子會重新開機,所以不能用 WiFi 改):

1. 切到這一頁時會自動讀板上目前的 WiFi 設定(也可以按「讀取板上設定」).
2. 選板子怎麼連網:
   - **板子自己開熱點**(出廠方式):手機直接連板子的 WiFi,不需要其他網路. 熱點名稱固定開頭 `HappySuperGG_Plane`,後面可以接數字或名字
     (最多 14 個英數字,同場好幾架才分得出來);熱點密碼 8~63 個英數字,出廠 `12345678`.
   - **板子連到家用 WiFi 或手機熱點**:手機和板子連同一個網路. 「WiFi 名稱」可以按「搜尋附近 WiFi」從下拉清單點(板子掃到的 2.4GHz 網路,依訊號排序),再填密碼.
     **手機熱點要開 2.4GHz 板子才看得到**:iPhone 在「個人熱點」打開「最大化相容性」;Android 在熱點設定把頻段選 2.4GHz. 連不上時板子會自動改開自己的熱點.
3. 按 **套用到板子並測試連線**:程式把設定寫進板子 → 板子重新開機 → 等 WiFi 就緒(最多等板子設定的秒數,預設 30 秒)→
   **連上了就自動固定(保持)**,並用大字顯示手機要開的網址:連家用 WiFi 顯示板子拿到的 IP(`http://192.168.x.x`;iPhone 與電腦也可以用 `http://lineplane.local`,
   Android 多半不認 `.local` 請用 IP),熱點模式顯示熱點名稱,密碼與 `http://192.168.4.1`.
   連不上(密碼錯,熱點是 5GHz,熱點沒開)會用紅字說明原因,並問要不要改回原本的設定;選「否」板子留在熱點模式,3 分鐘後自動改回.

**匯出板上設定備份…**:把板上**全部**設定(6 組飛行風格 + 起飛降落與安全 / 安裝 / 電變 / WiFi)存成文字檔,裡面是板子網頁「備份」頁用的設定備份碼.
板上有未儲存的變更時會先問要不要儲存(備份碼只能從已儲存的設定產生).

**匯入備份到板子…**:選備份檔,先檢查並顯示內容(哪幾組風格,哪些分區),確認後套用並儲存. 板上同名項目會被覆蓋.
含 WiFi 的備份套用後 WiFi 設定為「試用」,重新開機後 3 分鐘內要在網頁按「保持」,否則退回原本的 WiFi 設定(板子的安全機制).
備份檔也可以直接打開,把最後一行貼到板子網頁「備份」頁套用.

## 板子訊息(燒錄頁下方,序列監看)

顯示板子從 USB 送出的訊息(115200 bps),**常見的英文訊息翻成中文**(開機過程,WiFi 連線結果與網址,韌體版本,感測器,飛行狀態 …;
開機 ROM 的雜訊不顯示). 勾「顯示原始英文訊息」看板子的原文(回報問題時用).

- **板子狀態**:問板子韌體版本,WiFi 狀態(模式,網址,訊號),飛行狀態,感測器,中文顯示.
- **重新開機**:讓板子重新開機(馬達運轉或起飛程序中請不要按).
- **進階 ▸**:展開「送指令」列,可以輸入序列指令(`help` 列出全部;`fw` `net` `fs` `t` 是快捷鍵). 一般使用不需要.

板子重開或拔插 USB 時監看會自動重新連線. 「存成文字檔…」可以把訊息存下來回報問題.
程式開序列埠時不切換 DTR/RTS,所以打開監看**不會讓板子重開**. 設定網頁的 USB 通道也走同一條序列埠,訊息會夾在中間照常顯示.

## 開發者:自己打包

在 Windows 安裝 [Python](https://www.python.org/) 3.10 以上(python.org 安裝版內建 tkinter),執行:

```bat
tools\flasher\build_exe.bat
```

產出 `tools/flasher/dist/LineplaneConfig.exe`. 不打包直接跑:`pip install -r requirements.txt` 後 `python lineplane_config.py`.

GitHub Actions(`.github/workflows/flasher.yml`)在 `tools/flasher/` 有變更時用 Windows 自動打包,exe 放在該次執行的 Artifacts;
在 main 分支打包完直接建立/更新 Release「線控飛機設定器 v版本」(標籤 `config-v版本`)並設為最新,上面的固定網址就會拿到新版.
發新版前先改 `lineplane_config.py` 的 `APP_VERSION`(版本沒改時重跑會覆蓋同一版的 exe).

| 檔案 | 內容 |
|---|---|
| `lineplane_config.py` | 視窗介面(兩個分頁),燒錄流程(esptool 當函式庫呼叫),開機後檢查,設定網頁,WiFi 設定流程,備份匯出匯入,序列監看與訊息翻譯 |
| `board_link.py` | USB 設定通道電腦端(`@Q`/`@A` 協定),WiFi 連線,本機轉送伺服器,備份匯出匯入,WiFi 設定 API(讀/寫/搜尋/保持/重開,錯誤代碼中文) |
| `fw_image.py` | 韌體檔分析(類型,身分標記,晶片,分割表,映像檔校驗),boot_app0,版本清單,下載與組合 |
| `test_fw_image.py` / `test_board_link.py` | 單元測試(不需要網路與板子;`test_board_link` 用假板子照韌體的協定回應) |
| `requirements.txt` | 固定版本:esptool 4.12.0,pyserial 3.5,PyInstaller 6.11.1 |
| `build_exe.bat` | Windows 本機打包 |

### USB 設定通道協定(韌體 `src/web_server.cpp` r33 起)

板子的 38 個網頁 API 處理函式透過一個轉接物件同時服務 WiFi(WebServer)與 USB 序列埠. 電腦端送一行,板子回一段:

```
送:@Q <編號> <GET|POST> <F|T> <路徑?查詢>\t<本文百分比編碼>\n     F = 表單編碼(板子解成參數),T = 其他(本文放 plain)
收:@A <編號> <狀態碼> <本文長度> <內容類型>\n<本文 長度位元組>\n   本文可為二進位(飛行紀錄);板子其他訊息照常夾在中間
```

`/update`(韌體上傳)只走 WiFi,USB 回 `usbnoupload`. 一行請求上限 6000 位元組(板子 RX 緩衝 4KB).

版本清單與下載依賴公開韌體專案的命名(`tools/publish_firmware.py` 產生):Release 標籤 `v版本`,
韌體更新檔 `firmware-版本[-oled].bin`,完整燒錄檔 `lineplane-full-版本[-oled].bin`;讀不到 Releases(沒網路,GitHub API 次數用完)時
退回 `manifest.json` / `manifest-oled.json` 的最新版. 改發布工具的命名時要一起改 `fw_image.py`.
