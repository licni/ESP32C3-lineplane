# 雙向 DShot(eRPM 轉速回傳)與 EDT(溫度/電壓/電流)查證紀錄(2026-09-13)

GG 需求:解析 DShot 轉速回傳,可回報轉速;參考 Betaflight,甚至讀溫度,電壓,電流. **必須可選**(有些電變開了 RPM 回傳會解析失敗不工作).
由一位代理人讀原始碼查證(不是摘要). 版本:Betaflight `f1c74e2`(2026-09 master),Bluejay `0368d11`,AM32 `5bf674a`,EDT 規格 `438b879`.
Betaflight 路徑前綴 `https://github.com/betaflight/betaflight/blob/f1c74e2480a18820e18b75efa8a190b06aed9b40/`,行號以這些版本為準.

信心:已查證(官方原始碼/文件寫明)/ 部分查證(推論或作者陳述)/ 未查證.

## 對本專案影響最大的結論
1. **雙向 DShot 實務上要 DShot300 以上.** Bluejay 與 AM32 只認 DShot300/600;Betaflight 把 DShot150 雙向限制在 2kHz.
   DShot300 雙向最短週期 200µs,本專案 4kHz(250µs)做得到;DShot150 一個循環約 249µs,4kHz 下沒有餘裕.
2. **CRC 要取反**(控制器送出與電變回傳都是). EDT 規格 README 公式寫沒取反,但 Betaflight/Bluejay/AM32 原始碼都取反,以原始碼為準.
3. **Bluejay bootloader 陷阱**:沒有訊號狀態下,線持續高電位約 150ms 就進 bootloader(BLHeli_S 原版也有同樣檢查). 雙向閒置是高電位,ESP32 重開或 OTA 期間可能踩到.
4. **Betaflight 自己的 ESP32 驅動不支援雙向**(只發送),不能參考. ESP32 單腳收發有人回報切換毛刺,改用兩支腳.

### 解碼步驟
1. **21 → 20 位元(NRZI)**:電位有變化記 1,沒變化記 0;等效 `gcr = v ^ (v >> 1)` 取低 20 位元,丟掉起始位元.
   (brushlesswhoop;`dshot_bitbang_decode.c` L82;qqqlab L380). Betaflight 用相鄰邊緣時間差換算連續位元數 n,補 n 位元「100…」,最後一段與閒置高連在一起量不到就補足到 21 位元(`pwm_output_dshot_shared.c` L194-231).
2. **20 → 16 位元**:每 5 位元查表換 4 位元,由高位往低位.
3. **16 位元拆解**:`v12 = v16 >> 4`,`crc = v16 & 0xF`.

| 0 | 0x19 | 11001 |

## 三、同一條線的收發切換
### Betaflight STM32(已查證)
- 計時器 + DMA(`src/platform/STM32/pwm_output_dshot.c`):輸出推挽並開內部上拉(L303-312);送完 DMA 中斷裡把同通道改輸入擷取(雙邊緣,濾波 2,DMA 收最多 22 邊緣)(L182-216,L116-150,L343-348;`dshot.h` L42-43);下一週期先解碼再切回輸出(`pwm_output_dshot_shared.c` L260-329);切輸入後至少等 `35µs + 16×20 tick`(DShot300 約 88µs)才解碼(L417-418).
- GPIO bitbang(`dshot_bitbang.c`):訊框後**多送一個保持閒置電位的位元**才切輸入(有些 MCU 切換瞬間電位掉,電變讀錯最後一位元 CRC 錯)(L161-173);以回傳位元率 3 倍取樣(`dshot_bitbang_impl.h` L41,`dshot_bitbang.c` L418),收 140 取樣,DShot300 約 124µs(L421-425);**接收窗不可提早結束**,否則電變還在送時切回推挽會對打,曾干擾 AIO 板 I2C 氣壓計(L516-520).
- Pico:腳位開上拉,註明轉動中預期 5-8% 解碼錯誤(`dshot_bidir_pico.c` L55-60,L74).

### 更新率限制(已查證,`src/main/config/config.c` `validateAndFixGyroConfig()` L665-700)

### 電變不支援雙向卻收到反相訊框(部分查證)
- **BLHeli_S 原版**:輸入極性寫死(`BLHeli_S.asm` L3689),CRC 只做不取反檢查(L721-738) → 反相訊框 CRC 必定失敗,當範圍外訊號丟掉(從程式推論,沒有官方明文寫「不解鎖」).
- **Betaflight 端**:`dshot_bidir = ON` 時任一馬達沒回傳遙測就設 `ARMING_DISABLED_DSHOT_TELEM` 禁止解鎖(`fc/core.c` L429-436);RPM 濾波開但沒遙測 OSD 顯示 `RPMFILTER` 禁止解鎖. → GG 說的「勾了 RPM 回傳就不工作」有一部分是飛控端拒絕解鎖.
- **支援的韌體也可能出問題**:[bitdump/BLHeli #483](https://github.com/bitdump/BLHeli/issues/483) BLHeli_32 32.7.2 雙向 DShot300 依上電順序不同出現沒遙測,馬達也不轉,維護者未解釋.
- BLHeli_32 32.7 以前:閉源,未查證.
- **Bluejay bootloader 陷阱(已查證 `Bluejay.asm` L485-507)**:沒有訊號狀態(開機,或訊號中斷回 `init_no_signal` L681)下輸入線持續高約 150ms 就跳 bootloader;BLHeli_S 原版也有(L3594-3604). 雙向閒置高,加外接上拉時 ESP32 重開/OTA 可能觸發. 進 bootloader 後如何退出未查證.

## 五個重點
1. **DShot150 雙向在現行電變上走不通**:現行 Bluejay 與 AM32 都不接受 DShot150. 只有 Bluejay v0.8~v0.18.x 的 L 版(BB1,24MHz)支援過(GG 記得的應該是這個),2024-07 已整段刪除. 雙向用 DShot300.
2. **最危險是「線被拉高但沒有訊框」**:Bluejay 約 0.5 秒進 bootloader;AM32 沒訊號 2 秒(已解鎖 0.5 秒)重開,重開時線高就停在 bootloader. **恢復送 DShot 兩者都會自己跳出來**,不必斷電. 這個暴露在一般 DShot 也存在,不是雙向才有.
3. **Bluejay 的 EDT 只有溫度與狀態,沒有電壓電流**;AM32 與 BLHeli_32 32.10+ 才有溫度,電壓,電流.
4. **Rotorflight 沒有 EDT**(只取 eRPM);它的電變遙測除了 Castle Link Live 以外都要另一條線接 UART,本專案不能用.
5. **ESP32 單腳雙向有開源先例**(ESP32/S3),但沒找到 C3 當控制器端接真電變的. pioarduino 55.03.311(IDF 5.5)還有 `io_od_mode`/`io_loop_back`,IDF 6.0 已移除(改 `gpio_od_enable()`,同腳多驅動自動等效).

## 1. 飛控端腳位電位與上拉
- **計時器 DMA**:推挽輸出 + 內部上拉(反相接法才下拉);雙向只把輸出極性反相. BF `src/platform/STM32/pwm_output_dshot.c:303-312`,RF `src/main/drivers/pwm_output_dshot.c:286-294`. 收回傳時 `pwmDshotSetDirectionInput()` 改雙緣輸入捕捉(`:116-146`,`:345`),腳位設定不變 → 接收時只剩內部上拉. 【已查證】
- **Bitbang**:`bbPuPdMode` 上拉 + 推挽(`dshot_bitbang.c:813,835-837`);雙向閒置寫高(`dshot_bitbang_ll.c:67`);接收時 `bbSwitchToInput()` 只改 MODER 為輸入(`_ll.c:229-234`),上拉保留;送回輸出前先寫閒置電位(`:180-215`);`bbTelemetryWait()` 註解(`:514-523`):接收窗提早結束會推挽對上還在傳的電變,曾造成 3.3V 干擾(issue #15533). 【已查證】
- **外接上拉**:程式沒有任何要求,只用 MCU 內部上拉;電變傳遙測是推挽,飛控上拉只在空檔有作用. 【已查證】
- **開機/重開/DFU**:BF `init.c:562` motorDevInit,`:1052-1053` motorPostInit/motorEnable,之後每 PID 週期寫馬達(`core.c:1368-1391`),無寬限期. Bitbang 雙向初始化先 `IOLo`(`dshot_bitbang.c:815-846`),postInit 才改閒置高(部分查證). RF `core.c:136` `MOTORS_GRACE_TIME_US 2000000`,`:798` 開機 2 秒不送馬達訊框(腳位已閒置電位). DFU/重置期間由 MCU 預設決定,不在原始碼. 【BF/RF 已查證,DFU 未查證】

## 2. 電變端輸入腳上下拉
- **Bluejay/BLHeli_S(EFM8)**:開機 `P0 = P0_INIT (0FFh)`,`P0MDOUT = 0` → 開汲極輸出鎖存高(Bluejay `src/Bluejay.asm:419-423`,`Layouts/A.inc:61-62`;BLHeli_S `BLHeli_S.asm:3538-3541`,`A.inc:139-140`). XBR2 = `#40h`(Bluejay `Layouts/Base.inc:49-52`,BLHeli_S `A.inc:492`),WEAKPUD=0 = 全域弱上拉開. 傳遙測改推挽(`Modules/Isrs.asm:479-481`),傳完回開汲極 float high(`:62-65`). **沒接控制器時線高.** 【原始碼已查證;WEAKPUD 語意部分查證】
- **AM32**:主程式 `Src/main.c:1930-1934` 輸入腳開內部上拉(只有 NEUTRONRC_G071 開下拉),函式 `Mcu/f051/Src/IO.c:104-118`. bootloader `checkForSignal()`(AM32-bootloader `bootloader/main.c:1090-1153`)依序下拉,上拉,浮接探測. **沒接控制器時線高.** 【已查證】

## 3. bootloader 陷阱
- **Bluejay 觸發**:每個合法脈衝計數重設 10(`Isrs.asm:175,469`),Timer2 未解鎖每 32ms,解鎖後每 16ms 減一(`:508`) → 約 320/160ms 逾時 → 回 `init_no_signal`(`Bluejay.asm:678-681`) → 檢查線持續高約 150ms(`:496-508`),看到一次低就放行,持續高就嗶聲進 bootloader. **合計線高且沒訊框約 0.5 秒.** BLHeli_S 相同(`BLHeli_S.asm:3586-3605`,註解寫高超過 15ms). 【已查證】
- **Bluejay/BLHeli_S 退出**(`src/BLHeliBootLoad.inc`):`wait_for_low`(`:96-98`)線一直高就無限等;看到低後約 250ms `BOOT_DELAY`(`:9`)內找 "BLHeli" 簽名,逾時 exit `ljmp 0000h` 回主程式(`:101-117,189-197`);比對失敗重試 `Cmdh=250` 次用完也 exit(`:82,124`). → 恢復送 DShot,亂碼訊框讓它逾時或重試用完自動回主程式,重播開機音重新偵測. 【已查證;恢復時間推論】
- **AM32**:主程式沒訊號 0.5 秒(解鎖)/2 秒(未解鎖)`NVIC_SystemReset()`(`main.c:1992-2018`);bootloader 下拉下多數時間低就跳主程式,上拉下從沒看過低就留在 bootloader(`main.c:1110-1133`);退出:線持續低 20ms 設 `invalid_command=101` 跳主程式(`:836-846`),或 `invalid_command > 100`(`:1273-1274`),亂碼訊框每次加一. am32-firmware/AM32#312(2026-02):接收器開機把線拉高電變卡住,維護者:PWM 亂碼累積到門檻會跳主程式;使用者用 2k 下拉解決. 【已查證】
- **為何 BF 使用者少踩到**:初始化後每週期都送,電變開機音加等待本身數百毫秒以上(部分查證,時間推論). 「線拉高進 bootloader」是 BLHeli 直通設定的刻意設計:`esc4wayInit()` 把馬達腳改輸入上拉拉高(`src/main/io/serial_4way.c:129-158`);回主程式先送 Run 指令(`:619`)再拉低 300ms(`:620-627`). 【已查證】 沒找到「飛控重開後電變卡 bootloader」的 Bluejay/BF/RF issue,只有 AM32#312.
- **對本專案(未實測)**:ESP32 重開或 OTA 期間 GPIO4 大概浮接,加電變弱上拉 = 高;重開超過約 0.5 秒 Bluejay 進 bootloader,恢復送訊後自己出來. 一般 DShot 也同樣暴露. **不建議加下拉電阻**(雙向空檔電變只有弱上拉,加下拉會造成假邊緣,分析未查證). C3 GPIO4 重置期間實際電位要實測.

## 4. DShot150 雙向
- **Bluejay**(已查證):v0.1~v0.7 DShot150 程式被註解(v0.7 `Bluejay.asm:3616-3624` "TODO: dshot150 not supported");**v0.8**(2021-01-21,`f16cd2c` "Add DShot150 support on 24MHz MCUs")加入,只在 `MCU_48MHZ == 0` 編入,遙測位元率 187500(v0.8 `:3614-3629`),遙測依 `Flag_Rcp_DShot_Inverted` 對任何速率都送 → **v0.8 起的 L 版 DShot150 雙向可用**. 48MHz BB2(H)從不支援 DShot150. v0.19.0(2023-02)`6d8bb35` Makefile 只剩 H;2024-07 `fe95f3a` 刪除 BB1 與 DShot150;現行 main 只偵測 300/600(`src/Bluejay.asm:562-590`). **結論:只有 v0.8~v0.18.x L 版支援,現行不支援.**
- **AM32**(部分查證):`checkDshot()`(`Src/signal.c:200-229`)只接受兩個脈寬範圍,換算對應 600 與 300;DShot150 最短脈寬約 1.67µs(約 10 tick)不在範圍(依原始碼推算). README "Dshot(300, 600)". EDT 送電流,電壓,溫度(`Src/dshot.c:242-266`),電流 1A.
- **BLHeli_32**(部分查證):手冊 "Dshot is supported at any rate, up to at least Dshot1200","Rev32.10 and on support extended Dshot telemetry";48MHz MCU DShot 最低約 1000Hz;原始碼不公開.
- **Betaflight**(已查證):不擋 DShot150 雙向(只有非 DShot,burst DMA,N 通道計時器關雙向,`config.c:512-513`);DShot150 限 250µs,雙向乘 2 = 500µs = 2kHz(`config.c:676-678,697-700`);F4/G4 開雙向 DShot600 強制降 300(`:648-658`).
- **Rotorflight**(已查證):DShot150 上限 4000Hz,雙向除 2 = 2000Hz(`config.c:622-623,640-642`);官方文件建議 DShot150 或 300,不建議 600.
- **對本專案**:DShot150 訊框 107µs + 30µs + 回傳約 112µs ≈ 250µs 以上,4kHz 做不到(推論). 雙向選 DShot300(BF 上限 5kHz).

## 5. Rotorflight
- 雙向驅動與 BF 同源,上拉邏輯相同. **沒有 EDT**(master 與 RF-4.6.x `dshot.c` 無 EDT 解碼,只取 eRPM:`drivers/dshot.c:101`,`pwm_output_dshot_shared.c:130-182`). BF 有 `dshot_edt`(OFF/ON/FORCE,`cli/settings.c:1000`),解鎖時送指令 13(`fc/core.c:600-604` tryArm()). 【已查證】
- 馬達更新率:DShot 強制與 PID 同步 `useUnsyncedPwm=false`(`config.c:499-502`);預設 `pid_process_denom=8`(`flight/pid.h:30`),陀螺儀 8kHz 時 1kHz;`motor_pwm_rate` 預設 250(`pg/motor.c:40`,只對 PWM). 【部分查證】
- 設定名稱:`motor_pwm_protocol`(DSHOT150/300/600/PROSHOT1000/CASTLE…,`settings.c:290-293`),`dshot_bidir`(`:841`),`motor_poles`,`motor_rpm_lpf`,`dshot_bitbang`,`esc_sensor_protocol`,`esc_sensor_halfduplex`,`esc_sensor_pinswap`,`esc_sensor_update_hz`,電壓/電流/耗電修正(`:1571-1581`);設定工具 Motors 分頁「DShot RPM Telemetry」. 【已查證】
- 電變序列遙測協定(`settings.c:487-489`):OFF,BLHELI32,HOBBYWINGV4,HOBBYWINGV5,SCORPION,KONTRONIK,OMPHOBBY,ZTW,APD,OPENYGE,FLYROTOR,GRAUPNER,XDFLY,FBUS,SRXL2,RECORD. `escSensorInit()`(`sensors/esc_sensor.c:4453-4532`)要求 `FUNCTION_ESC_SENSOR` UART,19200/38400/115200 鮑率,可半雙工. **全部要另一條線,本專案不能用.** 例外 **Castle Link Live**:油門 PWM 與遙測共用一條線(`drivers/castle_telemetry_decode.c:103-106`,`esc_sensor.c:4230-4240`),50~100Hz;官方文件:自製轉接依 BEC 電壓配上拉(5V 配 5k). FBUS/SRXL2 走接收機匯流排. 【已查證】

## 6. ESP32 單腳可行性
- **rtlopez/esp-fc**(`5ae846a`,ESP32/S3,舊 RMT API,單腳):雙向只允許 300/600(`lib/EscDriver/src/EscDriverEsp32.cpp:99`);腳位開內部上拉,註解 "needed ?"(`:179`);**TX 完成中斷直接改 GPIO 矩陣關輸出接 RX**(`:250-289`),註解 "must not exceed 5-6us". 無解碼率數據;issue #121(2024-07)S3 DShot300 雙向錯誤率 100%,develop 修正後回報可用. C3 版是計時器 + 忙等 bitbang,不支援雙向(`EscDriverEsp32c3.cpp`),README 標 C3 experimental. 【已查證】
- **DrGlaucous/DShotRMT_NEO**(`b4b8277`,IDF 5 新 API,單腳,原版 ESP32):TX 開 `io_od_mode`,`io_loop_back`,`invert_out`,RX 也開 `io_loop_back`(`src/DShotRMT.cpp:238-259`);送出前關開汲極(`:348`),TX 完成 callback 開開汲極並啟動接收(`:61-78`). 作者自述接收可靠度原約 60%,改靜態陣列佇列後 99%(`README.md:114,197`);序列埠列印會讓下一包變短(`:202`). 【已查證,數據為作者自述】
- **MichelJansson/DShot-ESP32RMT**(`0e88a92`):TX/RX 都開 `io_loop_back`,`enableRx()` 切開汲極(`DShotRMT.cpp:67-110,290-295`),README 雙向只支援 DShot300 以上,無實測數據. 【已查證】
- **qqqlab/ESP32_DSHOT**(`4d0d78a`,原版 ESP32,IDF 4.4):TX 結束中斷切 RX 開上拉(`ESP32_DSHOT.cpp:364-372`);`arm()` 註解 "pull ESC line low (0.5 sec) - needed for BlueJay bidirectional"(`:94-107`),與 bootloader 陷阱吻合. 【已查證】
- **derdoktor667/DShotRMT**(`6e80e6a`):EXPERIMENTAL,要求外接 2k 上拉(`README.md:13`);「110 GCR bits 完整遙測」與協定不符,可信度低. 【部分查證】
- **wjxway/ESP32-Bidirectional-DShot**:兩支腳,"ESP32 will generate a glitch when switching between TX and RX"(`README.md:4`). 【README 說法】
- **C3**:只找到 H3rD3m1s3MyR1s3/esp32-dshot-sniffer `bidir/esc_emulator.c`(用 C3 **模擬電變**送回傳),提醒要推挽,弱開汲極上拉會讓脈寬變形(`bidir/README.md:22`). **沒找到 C3 控制器端接真電變的單腳雙向專案.**

- Espressif onewire_bus 用 `#if` 同時支援兩種 API(`onewire_bus_impl_rmt.c:285-296`),證明 C3 RMT 收發共腳可行,但 1-wire 時序寬鬆很多. esp32.com 討論串 t=26017,t=10419 讀不到(未查證).

## 7. CPU 負擔
- Betaflight ESP32 版不用驅動和中斷:每訊框直接把 17 個 symbol 寫進 RMT 記憶體,輪詢 TX_DONE 後啟動(`dshot_esp32.c:192-197,207-229`),每框幾十次暫存器存取. 【已查證】
- esp-fc 與 NEO 雙向每框兩次中斷:TX 完成(切開汲極與 RX,要求 5-6µs 內)+ RX 完成(解碼 21 位元 GCR,約 11 symbol 迴圈). 單馬達 4kHz = 每秒 8000 次中斷.
- 沒有 CPU% 或中斷耗時實測數據(未查證). 旁證:NEO 序列列印影響收包;esp-fc 要求 CPU 負載不超過 50-70%;BF 在 F4/G4 雙向強制 DShot300.
- 代理人估算(未查證):每次 ISR 數十 µs 內,單馬達 4kHz 約佔 C3 單核幾個百分點;真正風險是中斷延遲(DShot300 轉換窗只有 30µs),RMT 中斷優先權要實測.
