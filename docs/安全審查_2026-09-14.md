# 安全審查 2026-09-14

GG 提問:上電自動倒數會不會在家中、設定中、更新中誤觸發?自動啟動還能加什麼保護?飛行中會不會因為錯誤資訊或計時器出錯忽然失去動力?

審查範圍:flight.cpp(狀態機)、control.cpp(控制迴圈)、imu.cpp、impact.cpp、esc_output.cpp、esc_service.cpp、fw_update.cpp、wifi_manager.cpp、web_server.cpp、main.cpp、settings.cpp 的驗證與預設值、framework 的看門狗與電壓不足設定. 方法是逐條列出「會啟動馬達」與「會關掉或降低油門」的每一條路徑,再對每條路徑問「什麼情況會誤走到這裡」.

風險等級:**高** = 可能造成人員受傷或空中失去動力,建議一定要處理;**中** = 特定情況才會發生,建議處理;**低** = 已有防護或影響小,記錄備查.

## 第一部分:誤啟動(馬達在不該轉的時候轉起來)

### 目前已經有的保護(逐一對照程式確認)

### 發現

**A1【高】上電自動倒數模式:接上電池後,不需要任何人的動作,馬達就會轉**

流程:接電 → 3 秒解鎖 → 倒數(預設 20 秒,最少可設 5 秒)→ 馬達轉. 這是規格要的「資深飛友習慣」,但它同時也是整個系統最危險的一條路. 目前它會被擋下的條件只有:飛機沒放平、設定沒儲存、感測器壞、更新中. 在家裡把飛機放在桌上接電池「只是想看網頁」,這幾個條件通常都不成立,20 秒後馬達就轉.

另外兩個細節讓它更危險:
- 自動倒數**不等放穩**就開始倒數(程式註解:資深飛友習慣). 手勢模式要放穩 1 秒,自動模式不用.
- 「外力介入時」設成**不理會外力**時,抱著飛機走動也不會取消(只有傾斜超過 35° 持續 0.2 秒才取消).

建議(可以只做其中幾項):
1. **地面安全鎖**:網頁一個很大的「鎖定 / 解鎖」開關,存在 NVS. 鎖定時任何方式都不會啟動馬達(自動倒數、手勢、網頁開始),重開機仍然鎖著,只有網頁解鎖或 USB 指令能解. 在家調參數、改設定、更新韌體時先鎖上,到機場再解. 這是最有效的一道,而且不改變現有飛行流程.
2. 自動倒數也要**放平且靜止 1 秒**才開始倒數(和手勢模式一致).
3. 自動倒數模式的倒數秒數下限從 5 秒提高到 10 秒,人來得及反應.
4. 自動倒數模式時,網頁狀態列與監看頁用紅色大字提醒「上電自動倒數模式:接電池就會起飛」.
5. 出廠預設維持手勢模式(目前已是).

**A2【中】手勢模式:在家搬動飛機可能推到門檻**

推力門檻預設 2.0g,搬運時的加速通常小於這個值,而且推完還要放穩 1 秒 + 倒數 20 秒,搬運中多半會因傾斜被取消. 風險不高,但接著電池搬飛機時仍可能觸發倒數. 建議同 A1 的地面安全鎖.

**A3【中】撞擊斷電或緊急停止之後,推一下就能再起飛**

馬達停止後進入「已結束」狀態,手勢模式下推一下飛機就重新進入起飛程序. 撞機後跑去撿飛機、拉線、把飛機扶起來,都可能推到門檻. 有等待放穩與傾斜取消擋著,但不是 100%. 建議:撞擊斷電(END_CRASH)後不再接受推力手勢,要再飛必須網頁按「開始起飛程序」或重新上電.

**A4【中】電變校正旗標永久有效**

網頁按「下次通電進入校正」後,旗標存在 NVS,直到下一次真的拔電再接電才消耗. 如果按了之後沒有馬上做,幾天後裝著螺旋槳接電池,板子一開機就輸出**最高油門**並保持設定秒數. 網頁勾「螺旋槳已拆除」只是勾選,韌體無法確認.
建議:旗標加時效 —— 設定後板子在待機超過 10 分鐘就自動清掉旗標;軟體重開(網頁重開機、OTA)也清掉;校正開始前先閃燈 3 秒再輸出最高油門(給人最後一次拔電的機會).

**A5【低】板子上的 RESET 按鈕等於拔電再接電**

按 RESET 的重置原因和上電相同,自動倒數模式會重新倒數一次. 開發板的 RESET 鈕裝進飛機後碰不到,記錄備查.

**A6【低,但要知道】網頁 API 沒有任何驗證,熱點密碼固定且寫在公開專案**

任何連上板子網路的裝置都能送 /api/estop(飛行中關馬達)、/api/cancel、/api/start(手勢模式). 熱點密碼 12345678 寫在公開的 README. 同場的人只要知道就能連. 網頁自己有「連按三下」防誤觸,但直接打 API 不用.
這是 GG 決定的取捨(密碼固定避免使用者忘記). 如果要補強,可以只做一件事:飛行中(馬達轉動時)熱點不接受**新的**連線,已連上的手機照常可用. 家用 WiFi 模式風險較低,因為要先進得了家用網路.

## 第二部分:飛行中失去動力

### 會讓油門降到 0 或關馬達的每一條路徑

| 路徑 | 條件 | 判斷 |
|---|---|---|
| 網頁緊急停止 | 連按三下(API 一次) | 設計如此 |
| 撞擊斷電 | 開啟且 G 力 ≥ 門檻(預設 14g) | **見 B1** |
| 降落:觸地衝擊 / 靜止 / 滑行抖動 / 保險時間 | 只在降落程序中,減力走完後才判斷 | 設計正確 |
| 觸地提早降落 | 預設關閉;開啟時正飛水平 + 抖動持續達標 → 開始降落(減力,不是立刻停) | 設計正確 |
| 總飛行時間到 | 開始降落程序 | 設計正確 |
| 板子重新開機 | 電壓不足、當機、看門狗 → 電變沒訊號 → 馬達停 | **見 B2** |
| DShot 訊框沒送出 | 換值時硬體送框失敗 | **見 B3** |
| 補償把油門壓到下限 | 下限可以設 0% | **見 B4** |
| 韌體退回 / WiFi 設定退回 | 韌體待確認時不准起飛;WiFi 退回只重啟 WiFi 不重開板子(已實測) | 安全 |
| 感測器飛行中故障 | 補償停止照時間軸飛,不關馬達;撞擊與觸地判斷失效,降落靠保險時間 | 設計正確 |

### 發現

**B1【高】撞擊斷電只看一拍讀值,單筆錯誤資料就會關馬達,而且不可逆**

`in.accMagG >= fs.crashG` 只要一個 5 毫秒的讀值超過門檻就 finish. MPU6050 的 I2C 讀取沒有校驗碼,接觸不良或干擾時可能讀到一筆錯位的資料(數值任意大);感測器飽和(16g)那一拍也會算進去. 特技直角彎本來就 8~10g,和預設門檻 14g 只差 4g.
建議:**連續 2 拍(10 毫秒)都超過門檻**才算撞擊. 真的撞機衝擊持續遠超過 10 毫秒,不會漏掉;單筆壞資料擋得住. 另外飽和(saturated)的那一拍不採計,改用「連續飽和 2 拍」.

**B2【高,硬體】板子重新開機 = 馬達立刻停,程式救不了**

- 電壓不足:板子的偵測等級已經是最嚴格的 7 級. 馬達加速時電池電壓被拉低、BEC 供電不穩、接頭鬆動,都會讓板子重開. 事件紀錄第一筆會寫「電壓不足重新開機」,飛完可以查.
- 看門狗:Arduino loop 沒有訂閱任務看門狗(卡住不會重開),中斷看門狗 300ms 只在關中斷太久時觸發,快閃寫入只允許在待機. 目前程式不會被看門狗重開.
- 當機:程式錯誤. 已知的一次(mDNS)已修正,其他靠測試.
建議(硬體):板子供電走獨立 BEC 或加大電容,不要和舵機共用;接頭焊死. 程式面:重開後現在不會自動倒數,已是正確行為.

**B3【中】DShot 換值時送框失敗,會被記成已送出,之後不再重試**

writeDshot 在 rmt_transmit 失敗時仍把 dshotValue 更新成新值;油門不變的話就一直不送. DShot 電變沒訊號會自己停機(失訊保護). 平常 rmt_transmit 不會失敗(佇列剛清過),但這是一行就能修的漏洞:失敗時不更新 dshotValue,下一拍會再送. PWM 不受影響(硬體持續輸出).

**B4【中】飛行中油門下限可以設 0%**

補償曲線最多 −50%,下限設 0 時實際輸出可能到 0% = 馬達停. 這是設定值的問題,不是程式錯,但後果和失去動力一樣. 建議下限至少 10%(參數範圍改 10~100),或設低於 10% 時網頁警告.

**B5【中】飛行中仍有幾條路會寫入快閃記憶體**

寫快閃時整個處理器暫停幾毫秒到幾十毫秒,控制迴圈跟著停. PWM 與一般 DShot 由硬體持續輸出,馬達不會停;雙向 DShot 的送框計時器會延後,但電變失訊保護通常要幾百毫秒以上,不會觸發. 影響小但沒必要冒險. 飛行中會寫快閃的:WiFi 設定試用退回(改完 WiFi 設定重開後 3 分鐘內起飛)、網頁儲存 WiFi 設定(API 沒鎖)、檢查更新(不寫快閃但開一個 10KB 堆疊的下載工作). 建議:馬達轉動時這三項一律拒絕或延後到落地.

**B6【低】計時器與數值檢查,沒有發現問題**

- 飛行時間用 `now − motorStartMs`,毫秒計數 49 天才溢位,不影響.
- 倒數用固定 5 毫秒累減,控制迴圈延遲時倒數會變慢(安全的方向).
- 換段、降落減力、緩啟動、線長、單圈秒數的分母都有保護或有下限.
- 起飛時把設定拍成快照,飛行中網頁改值不影響這趟飛行.
- 控制迴圈延遲最長實測 16ms(WiFi 中斷),硬體維持電變輸出.
- 感測器 I2C 逾時 10ms,連續 10 次失敗才判故障,飛行中故障不關馬達.

## GG 的決定(2026-09-14)

- 不做軟體的地面安全鎖,改加**實體安全開關**:微動開關接 GPIO21,按下接地才能開始起飛程序(自動倒數與手勢都適用). 已實作並實測(flight r17,control r18).
- B1 撞擊斷電改連續 2 拍:已實作並實測.
- B3 DShot 送框失敗重試:已修正(esc_output r7).
- 第二批(GG:全做):A3 撞擊斷電後不接受推力手勢;A4 校正旗標時效(通電 10 分鐘沒拔電取消,軟體重開取消;校正前閃燈 3 秒不做,會改變電變上電第一個訊號時序);B4 飛行中油門下限最低 10%;B5 起飛程序與飛行中拒絕 WiFi 寫入,試用計時暫停到落地. 已實作並實測(safety2_test 32/32),發布 2026.09.14.8.
- A4 時效 GG 改定 10 秒(2026.09.14.9),網頁按鈕旁醒目提示. 限制:斷電期間沒有時鐘,「按了 10 秒內拔電,放幾天再接電」仍會校正. GG 決定不加「開機時安全開關要按下才校正」(會影響電變上電當下看到最高油門的偵測).
- 尚未處理:A1-2/3/4(自動倒數等放穩,倒數下限 10 秒,紅字提醒),A6(飛行中熱點不收新連線).
